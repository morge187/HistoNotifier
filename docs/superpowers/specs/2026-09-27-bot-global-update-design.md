# Глобальное обновление бота — дизайн

Дата: 2026-09-27
Исходное ТЗ: 10 пунктов (личный кабинет, обучение, меню, штрафы, оплата, GIF, приветствие, блокировка, правила, годы танков).

## Принятые решения

- Матч-штраф оплачивается **кадрами** или **Telegram Stars** по курсу 1 кадр = 5 ⭐ (звёзды = `ceil(cost * 5)`).
- Заблокированный пользователь на любое действие получает «🚫 Вы заблокированы». Админы блокировке не подвержены.
- Стоимость теста списывается **за каждую попытку**. Пройденный тест повторно не запускается.
- Порог прохождения теста — 80%. После неудачи — кулдаун 24 ч.
- Новая функциональность — в отдельных модулях; существующие файлы правятся точечно.

## Модель данных

`Base.metadata.create_all` не добавляет колонки в существующие таблицы, а `db.sqlite3` содержит живые данные. Поэтому `migrate.py` при старте (после `create_all`) проверяет `PRAGMA table_info` и выполняет `ALTER TABLE ... ADD COLUMN` для отсутствующих колонок. Миграция идемпотентна.

### Изменения существующих таблиц

| Таблица | Колонка | Тип | Значение для существующих строк | Для новых строк |
|---|---|---|---|---|
| `users` | `is_banned` | bool | `false` | `false` |
| `users` | `onboarded` | bool | `true` (приветствие не шлётся повторно) | `false` |
| `userrewards` | `issued` | bool | `true` (ссылки уже получены) | `false` |
| `battles` | `map_media_type` | str, nullable | `NULL` → трактуется как `photo` | `photo` / `animation` |

`users.fine` остаётся в схеме, но больше не используется.

### Новые таблицы

**`fines`**
- `id`, `user_id` (FK users), `description` (str), `cost` (float, кадры)
- `status`: `active` | `paid` | `removed`
- `created_at`, `closed_at` (nullable), `closed_by` (tg_id админа, nullable)
- `paid_with`: `cadrs` | `stars` | NULL
- `stars_amount` (int, nullable), `charge_id` (str, nullable — `telegram_payment_charge_id` для возможного возврата)

Однократный перенос: для каждого пользователя с непустым `users.fine`, если у него ещё нет записей в `fines`, создаётся запись `active` с `cost = 0` и `description = users.fine`.

**`tests`**: `id`, `title`, `cost` (float, 0 = бесплатно).

**`test_questions`**: `id`, `test_id` (FK, cascade), `position`, `text`, `option_1`…`option_4`, `correct` (1–4).

**`test_attempts`**: `id`, `user_id`, `test_id` (FK, cascade), `correct_count`, `total`, `passed` (bool), `created_at`.

## Главное меню

Пользователь (3×3):
```
[Личный кабинет] [Правила]         [🔍 Поиск]
[Матч-штрафы]    [Обучение]        [Награды]
[Список танков]  [Список сражений] [Список ивентов]
```

Админ: те же 9 кнопок, затем ряды «ивенты / награды / танки / сражения» (по 3 кнопки: добавить, изменить, удалить) и кнопка «Тесты ⚙️».

- «Награды» использует существующий обработчик `/rewards` (доступные награды + полученные внизу). Кнопки «Мои награды», «Список наград», «Мои кадры», «Поменять имя» убираются из клавиатур; команды `/my_rewards`, `/all_rewards`, `/my_cadrs`, `/rename` остаются.
- Обработчик матч-штрафов реагирует и на «Матч-штрафы», и на «матч-штрафы» (старые клавиатуры у пользователей).
- `/menu`: исправить опечатку в ответе; незарегистрированному пользователю — предложение нажать `/start`.

## Приветствие после регистрации

После успешного сохранения ника, если `onboarded == false`:
1. Бот отправляет инструкцию без клавиатуры меню (`ReplyKeyboardRemove`):
   ```
   📖 Как читать обозначения в боте:

   Pz. III A (Pz. III E)
   Официальное название техники (аналогичное название в игре).

   (Ред.) — техника или сражение сейчас редактируется.

   Если бот перестал отвечать после его удаления/перезапуска, напиши команду /menu — интерфейс восстановится.
   ```
   с инлайн-кнопкой **[Понятно!]**.
2. По нажатию: `onboarded = true`, кнопка убирается, отправляется клавиатура меню.

Смена ника у уже прошедшего онбординг пользователя приветствие не вызывает.

## Блокировка

- `middlewares/ban.py` — outer-middleware на `message` и `callback_query`. Если пользователь найден, `is_banned == true` и он не админ — отвечает «🚫 Вы заблокированы» (для callback — `callback.answer(..., show_alert=True)`) и не передаёт апдейт дальше.
- Пропускаются всегда: `pre_checkout_query` (другой тип апдейта) и сообщения с `successful_payment`, чтобы платёж, начатый до блокировки, не завис.

## Матч-штрафы (`handlers/fines.py`)

Переезд существующего кода из `handlers/admin.py` (режимы «Все игроки / По ивенту / По нику», изменение очков). Публичный режим показывает активные штрафы из таблицы `fines` (ник — список описаний).

Карточка игрока для админа показывает: ник, очки, статус, tg_id, число активных штрафов, признак блокировки. Действия:

- **Обнулить / Задать / Убавить очки** — без изменений.
- **Добавить штраф** — ввод описания, затем стоимости в кадрах (число ≥ 0, до 2 знаков после запятой). Создаётся запись `active`.
- **Штрафы игрока** — список активных штрафов, у каждого **[Снять]** → `status = removed`, `closed_at`, `closed_by`. Запись сохраняется.
- **Награды игрока** — список покупок (`userrewards`) с ✅/❌; нажатие переключает `issued`. При переключении в ✅ пользователь получает «🎁 Награда «X» выдана ✅».
- **Заблокировать 🚫** / **Разблокировать** (показывается одна в зависимости от состояния) → «Хотите ли вы оставить сообщение пользователю?» **[Да] [Нет]**.
  - Да → «Введите сообщение» → статус меняется, пользователь получает «🚫 Вы заблокированы.\n\n<текст>» (или «✅ Вы разблокированы.\n\n<текст>»).
  - Нет → статус меняется без уведомления.
  - Ошибка отправки уведомления (пользователь остановил бота) не отменяет смену статуса; админу сообщается, что уведомление не доставлено.

## Личный кабинет (`handlers/cabinet.py`)

Кнопка «Личный кабинет»:
```
👤 Ник: <name>
🎞 Кадры: <points> <эмодзи из cadr_tier>
🎁 Награды:
 • <reward> — выдан ✅ / не выдан ❌        (или «нет»)
📚 Тесты:
 • <test> — пройден 🟢 / не пройден 🔴      (все тесты; или «нет тестов»)
⚠️ Штрафы: нет
   или
 1. <description> — <cost> кадров
```

Инлайн-кнопки: **[💳 Оплатить штраф]** (если есть активные штрафы), **[✏️ Сменить ник]** (запускает существующий сценарий `Name.name`).

### Оплата

«Оплатить штраф» → список активных штрафов → выбор → **[🎞 Кадрами — N]** **[⭐ Звёздами — ceil(N*5)]**.

- **Кадры**: в одной транзакции проверить, что штраф `active` и `points >= cost`; списать кадры, `status = paid`, `paid_with = cadrs`, `closed_at`. Иначе alert «Недостаточно кадров» / «Штраф уже закрыт».
- **Stars**: `send_invoice(currency="XTR", provider_token="", prices=[LabeledPrice(amount=stars)], payload="fine:<id>")`.
  - `pre_checkout_query`: штраф существует, `active`, принадлежит плательщику, сумма совпадает → `ok=True`; иначе `ok=False` с причиной.
  - `successful_payment`: `status = paid`, `paid_with = stars`, `stars_amount`, `charge_id`, `closed_at`; подтверждение пользователю. Если штраф к этому моменту уже не `active` — всё равно записать `charge_id` в лог/сообщение админам для ручного возврата.
- Штраф стоимостью 0 (перенесённые старые) оплатить нельзя — кнопка оплаты для него не показывается; снимает только админ.

## Обучение

### Пользователь (`handlers/training.py`)

«Обучение» → список:
```
📚 Обучение

1. Тест А — 10 вопросов — бесплатно 🟢
2. Тест Б — 25 вопросов — 5 кадров 🔴
```
Выбор теста → карточка + **[▶️ Начать]**. Проверки перед стартом по порядку:
1. Есть попытка с `passed = true` → «✅ Тест уже пройден».
2. Последняя неудачная попытка моложе 24 ч → «Попробуй через Xч Yмин».
3. `points < cost` → «Недостаточно кадров».

Старт: списать `cost`, загрузить вопросы в FSM. Вопросы по одному, 4 инлайн-кнопки. После ответа кнопки у вопроса убираются. В конце:
- `correct / total >= 0.8` → «✅ Тест пройден! n из z верно».
- иначе → «n ошибок из z. Попробуй ещё раз через 24 ч.»

Попытка записывается в `test_attempts` в конце. Брошенный тест: стоимость не возвращается, попытка не записывается, кулдауна нет. Если тест удалён/изменён во время прохождения — ответ проверяется по данным из FSM, запись попытки для удалённого теста пропускается.

### Админ (`handlers/admin_training.py`)

«Тесты ⚙️» → **[Создать] [Изменить] [Удалить]**.

- **Создать**: название → стоимость (≥ 0) → количество вопросов (1–25) → для каждого: текст вопроса → 4 варианта одним сообщением (ровно 4 непустые строки) → правильный вариант кнопками **[1][2][3][4]**. Сохранение в БД после последнего вопроса; отмена на любом шаге ничего не создаёт.
- **Изменить**: выбор теста → название / стоимость / вопрос (текст → варианты → правильный) / **[+ Добавить вопрос]** (если < 25) / **[− Удалить вопрос]** (если > 1).
- **Удалить**: с подтверждением; каскадно удаляются вопросы и попытки.

Вне объёма: перемешивание вопросов/вариантов, таймер, разбор ошибок.

## Сражения: GIF

При добавлении и изменении карты принимаются `F.photo` и `F.animation`. Сохраняется `map_photo_id` + `map_media_type`. Показ: `answer_animation` для `animation`, иначе `answer_photo`. Удаление сообщения с картой (message_id в callback_data) работает для обоих типов.

## Танки: годы диапазоном

`utils.parse_years(text) -> list[int]`:
- принимает элементы через запятую; элемент — год или диапазон `A-B` (дефис, `–`, `—`, пробелы вокруг допустимы);
- проверки: `A <= B`, все годы в `[1900, текущий год]`; при ошибке — `ValueError` с понятным текстом;
- результат без повторов, отсортирован.

Используется при добавлении танка и изменении годов. Подсказка: «Например: 1941-1945 или 1939, 1941-1943».

## Правила

Блок наблюдателей: «Участникам кланов [Т-70В] и [RENWA]».

## Обработка ошибок

- Каждое админское действие (сообщение и callback) заново проверяет `is_admin`.
- Нажатия на устаревшие кнопки (штраф закрыт, тест удалён, игрок не найден) → короткий alert, без исключений.
- Ввод «Отмена» в любом новом FSM-сценарии сбрасывает состояние.

## Тестирование

- pytest для чистых функций: `parse_years`, `fine_stars(cost)`, оценка результата теста (порог 80%), расчёт оставшегося кулдауна.
- Миграция — прогон на копии `db.sqlite3`, проверка колонок и переноса штрафов, повторный прогон без изменений.
- Ручной чек-лист сценариев в Telegram — в плане реализации.
